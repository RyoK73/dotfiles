## このスキルがやること

Issueにしたい内容を、既存のopen Issueと照合する。
照合の結果に応じて、次のいずれかを行う。

- 新規: タイトル・本文・ラベルの案を作り、ユーザーの承認を得てから、`gh issue create` で1件作成する。
- 重複: 何もしない。
- 追加: 既存Issueに、コメントで情報を足す。
- 更新: 既存Issueの本文を編集する。

いずれも、書き込む前にユーザーの承認を得る。
ブランチの作成や実装はしない。
複数のIssueを作るときは、1件ずつ、手順 2 から繰り返す。

## 手順

### 1. 事前チェック

```
gh auth status
git remote get-url origin
```

`gh` が未認証なら、「`gh auth login` が必要です」と伝えて終了する。
origin が `github.com` を指していなければ、その旨を伝えて終了する。

### 2. 題材を確認する

`$ARGUMENTS` と直前の会話から、Issueにしたい内容を読み取る。
題材が曖昧で複数の解釈が成り立つ場合は、決めつけずにユーザーへ確認する。

### 3. コードを確認する

題材に関係するファイルを `Read` して、事実を確認する。
コードを読めば確定する事実は、ユーザーに質問しない。

### 4. 既存Issueを確認する

```
gh issue list --state open --limit 100 --json number,title,body
```

closed のIssueは対象にしない。
類似する候補があれば、`gh issue view <番号> --comments` で本文とコメントを読み、次の4つのいずれかに判定する。

| 判定 | 基準                                                                         | 動作                                   |
| ---- | ---------------------------------------------------------------------------- | -------------------------------------- |
| 新規 | 類似するIssueがない                                                          | 手順 5 以降で新規作成する              |
| 重複 | 既存Issueが、同じ内容をすでに書いている                                      | 何もしない。番号だけ報告する           |
| 追加 | 同じ問題だが、既存Issueにない情報(場所・根拠・修正案・再現条件)がある        | 既存Issueにコメントする                |
| 更新 | 既存Issueの本文が、古い・誤り・不足している                                  | 既存Issueの本文を編集する              |

- 判定は提案にとどめ、決めつけない。
- 番号・タイトル・判定の理由を示し、`AskUserQuestion` で「新規 / 重複 / 追加 / 更新」から選んでもらう。
- 類似するIssueが複数ある場合は、対象にするIssueも選んでもらう。
- 他のスキル(例: `pr-review`)から判定済みの内容を渡された場合は、その判定を使う。再度の選択は求めない。ただし、手順 7 の承認は省略しない。
- 判定が「重複」なら、手順 9 に進む。
- 判定が「追加」「更新」なら、手順 5 は省略し、手順 6 に進む。

### 5. テンプレートとラベルを確認する

Issue テンプレートがあれば、それを優先する。

```
ls .github/ISSUE_TEMPLATE .github/ISSUE_TEMPLATE.md .github/issue_template.md 2>/dev/null
```

- 該当するテンプレートが1つなら、その見出し構成に沿って本文を書く。
- 複数あれば、題材に合うものを選ぶ。判断できなければユーザーに聞く。
- テンプレートの `labels` や `title` の指定があれば従う。
- テンプレートがなければ、手順 6 の既定の書式を使う。

ラベルは `gh label list` の既存ラベルから選ぶ。
新しいラベルは作らない。

### 6. 案を作る

判定が「追加」の場合は、既存Issueに足すコメントの案を作る。
既存Issueにすでにある内容は繰り返さず、足りない情報だけを書く。

判定が「更新」の場合は、更新後の本文の案を作る。
既存の本文のうち、直す必要がない部分は変えない。
タイトルとラベルは、ユーザーが求めたときだけ変える。

判定が「新規」の場合の既定の書式（テンプレートがない場合）。

```
## 背景

<なぜこのIssueが必要か>

## やること

- [ ] <作業項目>

## 完了条件

- <Done の定義>
```

- 言語は日本語にする。
- 句点（`。`）の後で改行する。
- タイトルに `feat:` などのプレフィックスは付けない。
- 実装済みの機能として書かない。コードで確認した事実だけを事実として書く。
- 確認済みの事実と、推測による記述を区別する。推測を含む場合は、案の下に「〇〇は推測です」と明記する。
- 機能のアイデアや改善案は、Issueの本文に含めてよい（ドキュメントではなくIssueで管理する方針のため）。

### 7. 案を提示して確認を得る

案を表示し、ユーザーの自由入力の返答を待つ。

- 新規: タイトル、ラベル、本文を表示する。
- 追加: 対象のIssue番号とタイトル、コメントの全文を表示する。
- 更新: 対象のIssue番号とタイトル、変更前の本文と変更後の本文を並べて表示する。

他のスキル（例: `pr-review`）から呼ばれた場合も、この手順は省略しない。

- 承認（「OK」「ok」「はい」「LGTM」「お願いします」など）なら手順 8 に進む。承認かどうか曖昧な返答は、作成せずに聞き返す。
- それ以外は修正指示として扱う。指示を反映して再提示し、承認を得るまで繰り返す。

### 8. 書き込む

本文またはコメントを scratchpad のファイルに書き出し、`--body-file` で渡す。

新規:

```
gh issue create --title "<タイトル>" --label "<ラベル>" --body-file <本文ファイル>
```

ラベルが複数なら `--label` を繰り返す。
ラベルがなければ `--label` は付けない。

追加:

```
gh issue comment <番号> --body-file <コメントファイル>
```

更新:

```
gh issue edit <番号> --body-file <本文ファイル>
```

タイトルやラベルを変えるよう求められた場合だけ、`--title` や `--add-label` を足す。

### 9. 報告する

実行した動作(新規作成 / 重複のため何もせず / コメント追加 / 本文更新)を報告する。
あわせて、Issue の番号と URL を報告する。
新規の場合は、付与したラベルも報告する。

### 10. 作成が失敗したとき

エラー内容をそのまま報告する。
原因が自動で直せる場合（存在しないラベル名など）は、修正案を提示して承認を得てから再実行する。
承認なしにリトライしない。
